# UI ドッキングシステム 仕様書

## 1. 概要

Unityエディターのようなドッキング可能なUIシステムを実装する。ImGuiの`ImGuiDockNode`を使用して、ウィンドウの移動・リサイズ・ドッキング機能を提供する。

## 2. 機能要件

### 2.1 ドッキング機能の範囲

以下の機能を実装する：

- **ウィンドウの自由な移動・リサイズ**
  - すべてのドッキング可能なウィンドウは、マウスドラッグで自由に移動可能
  - ウィンドウの端をドラッグしてリサイズ可能

- **ウィンドウ同士のドッキング**
  - ウィンドウを他のウィンドウの端にドラッグしてドッキング可能
  - タブ化：複数のウィンドウを同じドッキングスペースに配置してタブ表示
  - 分割：ウィンドウをドラッグして既存のドッキングスペースを分割
  - 結合：ドッキングされたウィンドウを再配置して結合

- **フローティングウィンドウ**
  - ドッキングされたウィンドウをドラッグしてドッキング解除（フローティング化）可能
  - フローティングウィンドウは独立して移動・リサイズ可能

- **ドッキング状態の保存・復元**
  - ~~起動時に前回のレイアウトを自動復元~~（実装は一旦保留）

### 2.2 技術的な選択

- **実装方式**: ImGuiの`ImGuiDockNode`を使用
- **ImGuiの設定**: `ImGuiConfigFlags_DockingEnable`を有効化

## 3. ウィンドウの分類

### 3.1 ドッキング可能なウィンドウ

以下のウィンドウはドッキング可能とする：

| ウィンドウ名 | クラス名 | 説明 |
|------------|---------|------|
| Game Object Window | `DrawGameObjectWindow` | ゲームオブジェクトの編集ウィンドウ |
| Mode Window | `DrawModeWindow` | エディターモード/プレイモード切り替え |
| Post Process Preset Window | `DrawPostProcessPresetWindow` | ポストプロセスプリセット選択 |
| Models Window | `DrawModelsWindow` | モデル一覧と追加 |
| Task Manager Window | `DrawTaskManagerWindow` | タスク管理 |
| Work Manager Window | `DrawWorkManagerWindow` | ワーク管理 |

### 3.2 ドッキング不可能なUI要素

以下のUI要素はドッキング対象外とする：

| UI要素 | クラス名 | 理由 |
|--------|---------|------|
| メインメニューバー | `DrawDayWindow::draw()`内の`ImGui::BeginMainMenuBar()` | アプリケーションの最上部に固定すべきUI要素のため |

**実装方針**:
- メインメニューバーは`DrawDayWindow`から分離し、メインループで独立して描画
- または、`DrawDayWindow`を2つの部分に分割：
  - メニューバー部分：ドッキング不可能（固定描画）
  - その他のUI部分：ドッキング可能（別ウィンドウとして実装）

## 4. 最小サイズ制限

各ウィンドウに適切な最小サイズを設定する。これにより、ウィンドウが小さくなりすぎて操作不能になることを防ぐ。

### 4.1 最小サイズの設定方法

ImGuiの`ImGui::SetNextWindowSizeConstraints()`を使用して設定する。

### 4.2 各ウィンドウの最小サイズ

| ウィンドウ名 | 最小幅 | 最小高さ | 理由 |
|------------|--------|---------|------|
| Game Object Window | 400px | 300px | 内部に複数のChildウィンドウがあり、最低限の表示領域が必要 |
| Mode Window | 260px | 100px | 現在のサイズを最小サイズとして設定 |
| Post Process Preset Window | 200px | 100px | コンボボックスとボタンが表示可能なサイズ |
| Models Window | 250px | 200px | モデル一覧が表示可能なサイズ |
| Task Manager Window | 400px | 300px | タスク一覧と編集UIが表示可能なサイズ |
| Work Manager Window | 800px | 400px | 3カラムレイアウトが適切に表示されるサイズ |

**注意**: 実際の実装時に、各ウィンドウの内容を確認して適切な値を調整する。

## 5. ウィンドウ管理

### 5.1 ウィンドウの表示/非表示

- すべてのドッキング可能なウィンドウは、閉じるボタン（×）で非表示にできる
- 非表示になったウィンドウは、メニューバーから再表示可能

### 5.2 メニューバーからの再表示

メインメニューバーに「Window」メニューを追加し、以下の構造で各ウィンドウの表示/非表示を切り替え可能にする：

```
Window/
  ├─ Game Object Window
  ├─ Mode Window
  ├─ Post Process Preset Window
  ├─ Models Window
  ├─ Task Manager Window
  └─ Work Manager Window
```

**実装方針**:
- 各ウィンドウクラスに表示フラグ（`bool m_isVisible`など）を追加
- `IDrawWindow`インターフェースに`is_visible()`と`set_visible(bool)`メソッドを追加
- メニューバーの「Window」メニューから各ウィンドウの表示/非表示を切り替え
- `Engine::DrawImGui()`で、`is_visible()`が`true`のウィンドウのみ描画

### 5.3 ウィンドウの状態管理

- ウィンドウの表示/非表示状態は、アプリケーション実行中のみ保持
- アプリケーション終了時に状態はリセット（次回起動時はすべて表示）

## 6. 実装の優先順位

1. **Phase 1: 基本実装**
   - ImGuiDockNodeの有効化
   - 既存ウィンドウの固定位置・サイズ制限の解除
   - 最小サイズ制限の実装

2. **Phase 2: ウィンドウ管理**
   - ウィンドウの表示/非表示機能
   - メニューバーからの再表示機能

3. **Phase 3: メニューバーの分離**
   - `DrawDayWindow`からメニューバー部分を分離
   - メニューバーをドッキング不可能な固定UIとして実装

4. **Phase 4: レイアウト保存**
   - ドッキング状態の保存/復元機能
   - 設定ファイルへの保存

## 7. 懸念点と対策

### 7.1 DrawGameObjectWindow

**懸念**: 内部に複数の`ImGui::BeginChild`を使用しており、ウィンドウが小さくなると表示が崩れる可能性がある。

**対策**: 
- 最小サイズを適切に設定（400px × 300px）
- 必要に応じて、内部のChildウィンドウのサイズを相対値に変更

### 7.2 DrawWorkManagerWindow

**懸念**: `ImGui::Columns(3)`を使用した3カラムレイアウトのため、ウィンドウが狭くなるとカラムが適切に表示されない。

**対策**:
- 最小幅を800pxに設定
- 将来的には、カラム幅の調整機能を追加することを検討
